# 定制化空间盘点：在这条链上，我们能改到哪一步

日期：2026-10-29 · 结论先行：**只有三层能用**——HTTP/WS 语义层（最安全，已用掉大半）、页面注入层（能做，但每项都要"识别 + 自愈 + 回退"）、客户端层（PWA/Service Worker，收益最大、风险也最大）。改 DSH 本体不在表内。

## 一 判断标准

一条定制值不值得做，过四问：

1. **有没有稳定钩子**（状态属性/几何特征），还是只能靠猜类名？
2. **失效后果**是"难看"还是"不能用"？
3. **能不能一条命令退回**？
4. **收益**能不能在动手前估出来（秒 / KB / 像素）？

过不了 1 和 3 的，一律不做。

### C. 客户端层（超出代理，但同源可注入）

| # | 能力 | 状态 | 收益 | 风险 |

| C1 | 注册 Service Worker：资源 + 只读 API 落盘缓存 | ⬜ **下一步最有价值** | 冷启接近瞬时（连"重开"都不用出海） | **高**：版本错配会白屏，必须有版本号 + 一键注销 |

### D. 不做

- 改 DSH 打包产物（压缩代码 + 日更，一次升级全断）
- 浏览器端 E2E（客户端是服务端下发的 JS）
- 改 WS 协议帧语义（A6）

## 三 现有注入原语（复用的三件）

1. **属性标记 + 一条 CSS**：认到元素 → 打 `data-dshp*` → 一条 `!important` 规则。
2. **左移 + 加宽**：不跟应用抢布局计算，把盒子整体挪出去/撑开（B1、B2 都用它）。
3. **自愈**：应用后 300–700ms 复核关键尺寸，不达标自动撤销并记 `localStorage`，永不再试。

## 四 下一件该做什么

~~**C1（Service Worker）**~~ **已由用户否决（2026-10-29）**：原本是唯一还能把"冷启动"从秒级压到毫秒级的杠杆：它把静态资源与只读 API 存到**浏览器本地**，重开页面连代理都不用过。代价是版本一致性——必须给缓存打版本号、升级时清旧、并提供"注销并刷新"的逃生口。

B3/B5（字号、配色）与 B4/B6/B8 一并由用户否决（2026-10-29）：判定「没有价值」。
